# ADR 001 Document-First подход

## Статус

Актуально

## Контекст

Подход Document-First предполагает создание документов описывающих архитектурные решния, сущности модели предметной области, схемы модели хранения данных и внутренней архитектуры компонентов системы до начала этапа реализации. Это позволит:

* Хранить не только само принятое решение но и его контекст, описание важных факторов повлиявших на его принятие.

* Валидировать и вносить возможные правки в решения до начала их реализации, что позволит сократить время необходимое на разработку и уменьшит количество ошибок.

* Позволит делегировать некоторые этапы разработки ИИ агентам

## Решение

Необходимо вести документы:

* ADR (Architecture desi - записи архитектурных решений. Ведется в виде Markdown файлов с диаграммами илюстрирующими взаимодействие сервисов

* PDM - (Physical Data Model) - модель данных. Ведется в виде схемы таблиц БД каждого сервиса с отображением отношений между таблицами

* Domain Model - схема доменной модели. Ведется в виде UML диаграмм классов для каждого сервиса

* API - Описание публичного API сервиса. Ведется в виде контрактов OpenAPI для каждого сервиса

## Последствия

Подход Document-First позволяет сохранять описание принятых решений вместе с контекстом и алтернативными вариантами.
