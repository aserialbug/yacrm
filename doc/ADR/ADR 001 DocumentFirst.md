# ADR 001 Document-First подход

## Статус

Разрабатывается

## Контекст

Подход Document-First предполагает создание документов описывающих архитектурные решния, сущности модели предметной области, схемы модели хранения данных и внутренней архитектуры компонентов системы до начала этапа реализации. Это позволит:

* Хранить не только само принятое решение но и его контекст, описание важных факторов повлиявших на его принятие.

* Валидировать и вносить возможные правки в решения до начала их реализации, что позволит сократить время необходимое на разработку и уменьшит количество ошибок.

* Позволит делегировать некоторые этапы разработки ИИ агентам

## Решение

Необходимо вести документы:

* ADR (Architecture decision record) - записи архитектурных решений. Содержит набор файлов фиксирующих архитектурные решения в хронологической последовательности. Ведется в виде markdown файлов с текстовым описанием решения диаграммами илюстрирующими взаимодействие сервисов.

* PR (Product Requirements) - Требования к продукту. Содержит набор бизнес-требований к продукту. Требования включают описания сущностей и объектов предметной области. Фиксируют инварианты модели и ограничения и правил валидации атрибутов объектов предментной области. Ведется в виде markdown файлов

* CD (Class Diagrams) - Диаграммы классов. Набор файлов содержащих UML диаграммы классов каждого слоя сервиса в отдельности.

* TS (Technical Solutions) - Технические решения. Каждое техническое решение содержит конкретный список изменений, которые должны быть внесены в код для реализации каждого требования к продукту PR в виде markdown файла. Файлы имеют номер, соответсвтующий номеру PR.

* PDM - (Physical Data Model) - модель данных. Содержит набор ERD (Entity Relation Diagram) диаграмм в виде UML для каждого требования к продукту и имеют номер соответствующий номеру PR.

* Domain Model - схема доменной модели. Ведется в виде UML диаграмм классов для каждого сервиса

* API - Описание публичного API сервиса. Ведется в виде YAML файлов содержащих описание контрактов в формате OpenAPI 3.1.0 для каждого сервиса

## Последствия

Подход Document-First позволяет сохранять описание принятых решений вместе с контекстом и алтернативными вариантами.
