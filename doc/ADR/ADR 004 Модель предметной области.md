# ADR 004 Модель предметной области

## Статус

Разрабатывается

## Контекст

Необходимо зафиксировать подходы используемые при проектировании модели предметной области

## Решение

В модели предметной области есть два типа объектов:

### Сущности

Объекты уникально идентифицируемые по своему идентификатору и поддерживающие обновление значений своих атрибутов в течении жизни. Все классы сущностей являются производными от базового абстрактного класса сущности. Базовый класс для сущности является обобщенным и содержит параметр типа ограниченный классом базового идентификатора. Каждая сущность содержит идентификатор, который моделируется объектом-значением. Идентификатор сущености не может быть null. У сущности наряду с публичным конструктором, который позволяет задать все поля сущности должен быть статический фабричный метод для создания новой сущности в которм происходит генерация нового идентификатора и заполнения полей CreatedAt и UpdatedAt.

### Объекты-значения

Это неизменяемые объекты, которые описывают характеристики или свойства сущностей, но не имеют собственного уникального идентификатора. Их равенство определяется исключительно их содержимым. Для простых атрибутов модели должны создаваться отдельные объекты-значения. Объекты-значения должны иметь приватный конструкор и фабричный метод для создания их экземпляров. Объектоы-значения инкапсулируют логику валидации значений которые они представляют. Все объкты-значения для идентификаторов сущностей наследуются от базового абстрактного класса.

В модели предметной области не должно быть одержимости примитивами. Не обязательные атрибуты должны иметь значение null по-умолчанию.

## Последствия

Фиксирование подходов позволяет писать понятный код которй легко поддерживать
